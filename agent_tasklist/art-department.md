# 美工部的任务

美工部对照 `AESTHETIC.md` 产出美学判断；在专知路径内、任务明确实现时可直接改仓（`POWER-KNOWLEDGE.md`）。无权做产品终裁（监理部），无权记工作日志（书记）。可被总参谋部在规划中调度（父代理按单派出）。

## 先读

1. 美学真源：`agent_tasklist/AESTHETIC.md`（唯一美学判断与管辖路径依据）。
2. 权知边界：仓根 `POWER-KNOWLEDGE.md`。
3. 产品边界（只读、不代审）：`agent_tasklist/DESIGN.md` §2「统一审美 / 简洁」。
4. 概念边界（不改语义）：`ind-chain/CONCEPTS.md` 中与色、chrome、C-SPLASH 相关的指针。

## 父代理必须送来

1. 角色：`art-department`
2. 用户原话或本次美学目标（不改写）
3. 材料：将改或已改的外观相关路径 / diff；或「盘点现行美学」
4. 是否实现：写明「只出方案」或「专知内实现」
5. 交回：见角色文件（含 `已改路径`）

## 专知内可改

任务写明实现时，美工部可改 `AESTHETIC.md` §3 表内视觉路径。越界或与逻辑缠在一起：交父代理。有产品代码改动时，由**父代理**送监理部。
