# 给子代理写任务

子代理的角色在 `agents/`。本目录放每个角色对应的任务，创建角色之前先把任务放进来。四席平级：总参谋部、监理部、档案部、内阁。理念贯彻属的任务是 `agent_tasklist/DESIGN.md`，判断只以该文件为准。整单通过或打回只出自监理部三监报告。

父代理派子代理时按本文件写任务。子代理看不到当前对话，任务里要写全。

## 目的

工程变大、架构变复杂时，工作时间要更短。委派只用来拿掉一次多余的转手，不用来多开一轮。不该出现的席不派；该做的事在这一轮做完。各部门尽心竭力完成自己这一段，不把同一件事再派一遍。

## 电

「电」是点名前缀，可调出**任意**子代理。写法：`电` + 角色名（中文或 `agents/` 文件名），后面可接任务。例如：电总参谋部、电监理部、电档案部、电内阁、电美工部、电信息部、电参谋纪要官、电书记、电秘书、电运维。

只写「电」、没有角色名：不派。不要把单独的「电」当成总参谋部。单独「电参谋纪要官」而无总参谋部任务单「调度」句：不派（纪要官只经 GS 调度）。三属（工程测试、代码质量、理念贯彻）只经监理部委派；单独电某一属而无监理部材料：不派。

英文同义：`M` / `Message` 仍只叫总参谋部（见下节）。「报文」「报」亦只叫总参谋部。

旧词只改派、不保留旧职权：`电总监`、`总监`、`电监理处`、`监理处`、`chief inspector`、`产品理念监督` → 监理部；`电书记处`、`书记处`、`Secretariat` → 档案部。角色自称只用新名。

点名后仍守该角色自己的职权：电监理部仍只审已改完的代码（无 diff 则回「无代码改动，不审」，不空转三属）；电书记仍只记 worklog；谈话末项的书记不因是否电过而取消。

## 总参谋部

只在用户写出「电总参谋部」，或「报文」「报」「M」「Message」，或直接呼出总参谋部 / General Staff 时，父代理才派它。没有这些呼出，不派。单独的「电」不派总参谋部。

它一旦执行，必须是本次第一个做规划的代理。对话刚开始的内阁谏言可以在规划之前，那不算顺序错误；其后总参谋部仍是第一个做规划的代理。父代理按它交回的任务列表执行：其中可含对**除监理部、档案部、内阁以外**子代理的调度（美工部、信息部、参谋纪要官）；有「电总参谋部」且业主安排管理子代理时，还可含对那些角色文件的精确改文（父代理落盘，含 `staff-memo`）。**专知路径内**美工部 / 信息部可写码（见 `POWER-KNOWLEDGE.md`）；**跨域与未授权路径**仍由父代理写。凡有产品代码改动，仍由父代理送监理部（监理部委派三属 → 三监报告）；书记仍是谈话的最后一项。总参谋部不调度内阁。

它按 `agent_tasklist/general-staff.md` 阅读工作日志、概念和工程结构，交回「总参谋部规划」：意志 + 任务列表。全新问题可以由它提出创新方案。

**硬排除：** 总参谋部不调度、不指导、不改写监理部与档案部（含三属与书记、秘书、运维及其任务真源），也不调度内阁。父代理不得因 GS 规划去改 `supervision-department` / `engineering-test` / `code-quality` / `principle-compliance` / `archive-department` / `secretary` / `clerk` / `operations` 或其任务真源（`DESIGN.md`、`supervision.md`、`engineering-test.md`、`code-quality.md`、`archive-department.md`、`secretary.md`）。

调度落地：任务单默认没有调度句。没有调度句，就不派美工部、信息部、参谋纪要官。有调度句才调用 Task，`subagent_type` 对应该角色。总参谋部会话内不自行 spawn 其它子代理。

执行：意志已写明符号与文件时，父代理按该句改，不先跑一轮再查因。意志写死的那一串，父代理照抄，不另选。改界面文字时，父代理照抄意志里要删的原句和要留下的句子，不改写。审查标准不变。

## 美工部

美工部管统一网页与启动表层美学，对照 `agent_tasklist/AESTHETIC.md`；专知路径内可改码（`POWER-KNOWLEDGE.md`）。

调出时机：

1. 用户写出「电美工部」，或呼出「美工部」或「art department」
2. 父代理将改动启动图标、开屏、logo、全局 CSS / 玻璃 chrome、新建分页或整块 UI 面的视觉时——**必须先派美工部**
3. 总参谋部规划任务单写明「调度美工部」时——父代理按单派出

纯坐标、纯 API、无外观 diff：不派。

任务明确实现时，美工部可在 AESTHETIC 管辖路径内改仓；越界交父代理。有代码改动时，产品终审仍走监理部三监报告，不由美工部「通过/打回」；**送审口仍是父代理**。

任务写法见 `agent_tasklist/art-department.md`。

## 信息部

信息部管数据读取、调用词条、乱缺建议、以及彭博 Excel / BQLX 公式方案，对照 `agent_tasklist/INFORMATION.md` 与三分部文件。与美工部同级，隶属总参谋部调度；专知路径内可改码（`POWER-KNOWLEDGE.md`）。

调出时机：

1. 用户写出「电信息部」，或呼出「信息部」或「information department」
2. 需要读数、管数、立词条；或数据乱/缺需建议或上报业主；或要为工程补数生成扒取公式表
3. 总参谋部规划任务单写明「调度信息部」时——父代理按单派出

任务必须有 **`desk=`**（`manage` | `clean` | `request`）。交回格式见角色文件。任务明确实现时，可在 INFORMATION 管辖路径内改仓；不可改 `ind-chain/server/*` 与美学文件。有代码改动时送审口仍是父代理。

任务写法见 `agent_tasklist/information-department.md`。

## 参谋纪要官

参谋纪要官 `staff-memo` 是总参谋部的轻量助手，只对总参谋部负责。

调出时机：

1. **仅**总参谋部规划任务单写明「调度 `staff-memo` / 参谋纪要官」时——父代理按单派出（须有 `mode=`：`pin` | `open` | `reflux`）
2. 用户单独写出「电参谋纪要官」而无 GS 调度句：不派

默认只读、会话交回，不写 `library/`。**不因 POWER-KNOWLEDGE 获产品改码权**；不指挥/替代监理部与档案部。日后可由总参谋部经「电总参谋部」+明示安排改写其角色与任务文件。

任务写法见 `agent_tasklist/staff-memo.md`。

## 监理部

监理部是代码改动的终裁，不是规划会。父代理在三监报告交回之前，不能宣布这次代码改动已经完成。

调出时机：

1. 任务里的代码已经改完，把这一步放在书记之前。有代码修改时必须调出，没有例外。
2. 用户写出「电监理部」或旧词「电总监」「电监理处」，或直接呼出监理部 / 总监 / 监理处：即使无代码也要派；无 diff 则回「无代码改动，不审」，不空转三属。若点名同时改本部门规程，父代理落盘，仍不空转三属。

讨论、规划、还没改代码且未点名：不调出。

监理部对三属有委派权。流程见 `agent_tasklist/supervision.md`：父代理只把送审材料交给监理部（送审口）；有 diff 且次数不大于 3 时，监理部在本会话用 Task 并行委派 `engineering-test`、`code-quality`、`principle-compliance`（同一份材料，互不看对方结论），再交回一份三监报告。无 diff 不委派。某属类型未收录：该属交回「类型未收录，委派未落地」，父代理按单代派该属，已委派的属不再第二次点名；缺的那一属交回之前结论为「待三属」。三属都达标才通过；任一不达标整单打回；打回后三属整单重审。上限三次。

工程测试打开本地页面是本职。碰到拉取页面、打开页面的确认，直接通过，不再问业主。代码质量只读本地 diff，不打开 GitHub，不截图。截图只属于工程测试。

## 任务里必须有

1. 角色：`agents/` 里的文件名，例如 `supervision-department`、`engineering-test`、`code-quality`、`principle-compliance`、`art-department`、`information-department`、`staff-memo`、`archive-department`、`clerk`、`operations`。
2. 用户原话：本次要判断的那一句，不改写。三属必须拿到同一份原话。
3. 材料：已经发生的代码改动，写路径或 diff。不送计划。理念贯彻属的标准是 `agent_tasklist/DESIGN.md`；工程测试属看能否打开与影像；代码质量属只答四问。美工部的标准是 `agent_tasklist/AESTHETIC.md`；信息部的标准是 `agent_tasklist/INFORMATION.md`（及点名分部）。信息部任务还须有 `desk=`。参谋纪要官任务还须有 `mode=`。
4. 送审次数：写明「这是第 N 次送审」。第一次送审 N = 1。（监理部与三属沿用同一 N，自己不加）
5. 交回：整单只要三监报告。通过时不要建议。打回只转述不达标属已写的句子。美工部、信息部、参谋纪要官交回格式见其角色文件。

## 对话栏

三监报告交回后，父代理在对话里先写一句：

- 第 1 次通过：一次通过
- 第 2、3 次通过：第 N 次通过
- 打回：第 N 次打回

通过时不要另加建议。打回：按不达标属的句子改代码，改完三属整单重审，再把监理部作为书记之前的一步调出。

这一句写完之后、派书记之前，按下一节唤起内阁谏言。内阁不改这句结论。

## 内阁

内阁与总参谋部、监理部、档案部平级，不归三部统领。父代理直接唤起，不经三部转发。三部不调度内阁，内阁也不调度三部。

呼出：用户写出「电内阁」，或呼出「内阁」。单独的「电」不派。

任务只此三件，另有影像一条：

1. **整理**：数据、图件、新闻、分析报告。图件是图、表、示意图，不是应用程序图标或启动器图标。只写入仓库根目录 `cabinet/`。不写入 `library/worklog`、`showable-report/`、`bug-report/`。不派秘书。
2. **撰写**：业主向内阁要可打印报告时才写。报告库是 `cabinet/reports/`，没有就由内阁自行创建。纸面 token 与秘书相同。不写入 `library/showable-report/`。不派秘书。未点名内阁的报告、汇报、PPT 仍走档案部。
3. **谏言**：时机只两处。对话刚开始，任何规划与改码之前。监理部三监报告已经交回，父代理已写对话栏那一句之后，派书记之前。认为不需要，内阁只回「不发问」，父代理不弹窗，继续往下做。认为需要，内阁只回「发问」，并只写两句：这问是否合理；这令是否有助于工程完成。父代理弹出中途询问对话框，选项里有「强制实施」，然后停住，等业主答。最终决定权在业主。业主选强制实施，父代理按原令继续。内阁不否决、不代替实施、不改三监报告、不派书记。

**影像**：内阁读 PDF 可以自行把页面渲成图再看，不必只抽文字层，不必请示业主。渲染用本机已装的 PyMuPDF。缺了就自行安装，不必再请示。截图若留下，只放 `cabinet/`。

任务写法见 `agent_tasklist/cabinet.md`。

## 档案部

档案部与总参谋部、监理部平级。下属：书记 `secretary`、秘书 `clerk`、运维 `operations`。档案部拥有委派权：任务单点名的三席，由档案部在本会话用 Task 派出。

调出时机：

1. 用户写出「电档案部」或旧词「电书记处」，或呼出「档案部」「书记处」/ Secretariat
2. 用户要报告、汇报、PPT、展出、可打印读本/讲稿，且没有点名内阁 → 父代理只派档案部；秘书由档案部委派（**不是**每次谈话必派秘书）。点名电内阁并要可打印报告的，由内阁写入 `cabinet/reports/`，不改派秘书。
3. 运行出现 bug，或用户要记录 bug 与解法 → 父代理只派档案部；运维由档案部委派（**不是**每次谈话必派运维）

类型未收录则该席交回「类型未收录，委派未落地」，父代理按单代派该席；已派出的席不再第二次点名。谈话末项书记与电书记仍由父代理派。电秘书、电运维仍由父代理按点名直接派。总参谋部不调度档案部。不改 `ind-chain`，不改 `DESIGN.md`。

任务写法见 `agent_tasklist/archive-department.md`。

## 书记

书记隶属档案部，职能仍是 worklog。每次谈话都要出现。书记不参与决策。不写报告/PPT。

书记是最后一个任务。谈话里的事情全部做完才派，包括三监报告已经交回的情况。监理部排在书记前面。没有例外。不经档案部转发。这一次不写入档案部必派名单。档案部只委派非末项、且其任务确实需要的那一次书记。

书记的工作区是 `library/`。按 `agent_tasklist/secretary.md` 把用户的问题、任务、主代理和子代理的执行补进当前的 `worklog-xxx`。当前册超过 10000 字就另开下一册。用户说停，书记也不再派。

每条新流水的 A 末尾多记两样，不另加列，不改旧行。父代理派书记时必须带上本次执行时间（业主该条报文到派书记，单位分钟；不足 1 分钟写「不足1分」），不预填复杂度。

1. **复杂度**：0–10 的整数，对象是业主那条指令。有总参谋部下达的任务则据那份任务打分；没有则据业主原话。打多少分由书记定，父代理不改分。
2. **执行时间**：书记照父代理交来的时长记。用来看一次执行是否过长，供日后整改和精简部门。

## 秘书

只在业主要文稿或档案部委派时出现。「电秘书」、点名文稿、呼出「秘书」由父代理直接派。档案部的任务需要秘书时，由档案部在本会话用 Task 委派。不是每次谈话必派。落盘 `library/showable-report/`。见 `agent_tasklist/clerk.md`。

## 运维

只在故障已现或业主要记 bug 时出现。「电运维」或呼出「运维」由父代理直接派。故障已现，或业主要记 bug，由档案部在本会话用 Task 委派。不是每次谈话必派。落盘 `library/bug-report/ops-log-xxx.md`。见 `agent_tasklist/operations.md`。

## 停止

用户说「停止」「停」或 stop：不再派任何子代理。已经派出的，不再根据它的结果派下一次。

第 3 次仍是打回：停下来把三次结论告诉用户，不再派第 4 次。
