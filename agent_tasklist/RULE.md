# 给子代理写任务

子代理的角色在 `agents/`。本目录放每个角色对应的任务，创建角色之前先把任务放进来。总监的任务是 `agent_tasklist/DESIGN.md`，判断只以该文件为准。

父代理派子代理时按本文件写任务。子代理看不到当前对话，任务里要写全。

## 总参谋部

只在用户下达任务前写出「报文」「报」「电」「M」「Message」，或直接呼出总参谋部时，父代理才派它。没有这些呼出，不派。

它一旦执行，必须是本次第一个执行任务的代理。父代理按它交回的任务列表执行：其中可含对**除总监、书记处以外**子代理的调度；有「电」且业主安排管理子代理时，还可含对那些角色文件的精确改文（父代理落盘）。产品实现仍由父代理写码。有代码改动时再调总监；书记仍是谈话的最后一项。

它按 `agent_tasklist/general-staff.md` 阅读工作日志、概念和工程结构，交回「总参谋部规划」：意志 + 任务列表。全新问题可以由它提出创新方案。

**硬排除：** 总参谋部不调度、不指导、不改写总监与书记处（含书记、秘书、运维及其任务真源）。父代理不得因 GS 规划去改 `chief-inspector` / `secretariat` / `secretary` / `clerk` / `operations` 或其任务真源。

调度落地：父代理按任务单调用 Task，`subagent_type` 对应该角色（如 `art-department`、`information-department`）。总参谋部会话内不自行 spawn 其它子代理。

## 美工部

美工部管统一网页与启动表层美学，对照 `agent_tasklist/AESTHETIC.md`。

调出时机：

1. 用户呼出「美工部」或「art department」
2. 父代理将改动启动图标、开屏、logo、全局 CSS / 玻璃 chrome、新建分页或整块 UI 面的视觉时——**必须先派美工部**
3. 总参谋部规划任务单写明「调度美工部」时——父代理按单派出

纯坐标、纯 API、无外观 diff：不派。

美工部只交美学结论与延展要点，默认不改仓。有代码改动时，产品终审仍走总监（DESIGN），不由美工部「通过/打回」。

任务写法见 `agent_tasklist/art-department.md`。

## 信息部

信息部管数据读取、调用词条、乱缺建议、以及彭博 Excel / BQLX 公式方案，对照 `agent_tasklist/INFORMATION.md` 与三分部文件。与美工部同级，隶属总参谋部调度。

调出时机：

1. 用户呼出「信息部」或「information department」
2. 需要读数、管数、立词条；或数据乱/缺需建议或上报业主；或要为工程补数生成扒取公式表
3. 总参谋部规划任务单写明「调度信息部」时——父代理按单派出

任务必须有 **`desk=`**（`manage` | `clean` | `request`）。交回格式见角色文件。信息部默认不改仓。

任务写法见 `agent_tasklist/information-department.md`。

## 总监

总监是代码改动的终审，不是规划会。父代理在总监交回之前，不能宣布这次代码改动已经完成。

调出时机只有一个：任务里的代码已经改完，把这一步放在最后（美工部方案之后、书记之前）。讨论、规划、还没改代码时，不调出。没有代码改动的任务，不调出。有代码修改时必须调出，没有例外。

## 任务里必须有

1. 角色：`agents/` 里的文件名，例如 `chief-inspector`、`art-department`、`information-department`、`secretariat`、`clerk`、`operations`。
2. 用户原话：本次要判断的那一句，不改写。
3. 材料：已经发生的代码改动，写路径或 diff。不送计划。总监的标准是 `agent_tasklist/DESIGN.md`；美工部的标准是 `agent_tasklist/AESTHETIC.md`；信息部的标准是 `agent_tasklist/INFORMATION.md`（及点名分部）。信息部任务还须有 `desk=`。
4. 送审次数：写明「这是第 N 次送审」。第一次送审 N = 1。（仅总监）
5. 交回：总监只要结论；通过时不要建议。打回时要有「总监建议」，建议只能从 `agent_tasklist/DESIGN.md` 来。美工部、信息部交回格式见其角色文件。

## 对话栏

总监交回后，父代理在对话里先写一句：

- 一次通过
- 第 N 次打回

通过：在对话栏写「一次通过」，不要另加建议。打回：按「总监建议」改代码，改完再把总监作为最后一步调出。

## 书记处

书记处与总参谋部平级。下属：书记 `secretary`、秘书 `clerk`、运维 `operations`。

调出时机：

1. 用户呼出「书记处」
2. 用户要报告、汇报、PPT、展出、可打印读本/讲稿 → 先派书记处，再按单派秘书（**不是**每次谈话必派秘书）
3. 运行出现 bug，或用户要记录 bug 与解法 → 先派书记处，再按单派运维（**不是**每次谈话必派运维）

任务写法见 `agent_tasklist/secretariat.md`。总参谋部不调度书记处。

## 书记

书记隶属书记处，职能仍是 worklog。比总监更根本：每次谈话都要出现。书记不参与决策。不写报告/PPT。

书记是最后一个任务。谈话里的事情全部做完才派，包括总监已经交回的情况。总监排在书记前面。没有例外。不经书记处转发。

书记的工作区是 `library/`。按 `agent_tasklist/secretary.md` 把用户的问题、任务、主代理和子代理的执行补进当前的 `worklog-xxx`。当前册超过 10000 字就另开下一册。用户说停，书记也不再派。

## 秘书

只在业主要文稿或书记处调度时出现。落盘 `library/showable-report/`。见 `agent_tasklist/clerk.md`。

## 运维

只在故障已现或业主要记 bug 时出现。落盘 `library/bug-report/ops-log-xxx.md`。见 `agent_tasklist/operations.md`。

## 停止

用户说「停止」「停」或 stop：不再派任何子代理。已经派出的，不再根据它的结果派下一次。

第 3 次仍是打回：停下来把三次结论告诉用户，不再派第 4 次。
