# 给子代理写任务

子代理的角色在 `agents/`。本目录放每个角色对应的任务，创建角色之前先把任务放进来。总监的任务是 `agent_tasklist/DESIGN.md`，判断只以该文件为准。

父代理派子代理时按本文件写任务。子代理看不到当前对话，任务里要写全。

## 总参谋部

只在用户下达任务前写出「报文」「报」「电」「M」「Message」，或直接呼出总参谋部时，父代理才派它。没有这些呼出，不派。

它一旦执行，必须是本次第一个执行任务的代理。后面才是实现；有代码改动时再调总监；书记仍是谈话的最后一项。

它按 `agent_tasklist/general-staff.md` 阅读工作日志、概念和工程结构，交回「总参谋部规划」：意志 + 任务列表。全新问题可以由它提出创新方案。父代理按这份规划执行。总参谋部不改文件，无权指导总监，无权指导书记。

## 总监

总监是代码改动的终审，不是规划会。父代理在总监交回之前，不能宣布这次代码改动已经完成。

调出时机只有一个：任务里的代码已经改完，把这一步放在最后。讨论、规划、还没改代码时，不调出。没有代码改动的任务，不调出。有代码修改时必须调出，没有例外。

## 任务里必须有

1. 角色：`agents/` 里的文件名，例如 `chief-inspector`。
2. 用户原话：本次要判断的那一句，不改写。
3. 材料：已经发生的代码改动，写路径或 diff。不送计划。总监的标准是 `agent_tasklist/DESIGN.md`。
4. 送审次数：写明「这是第 N 次送审」。第一次送审 N = 1。
5. 交回：只要结论。通过时不要建议。打回时要有「总监建议」，建议只能从 `agent_tasklist/DESIGN.md` 来。

## 对话栏

总监交回后，父代理在对话里先写一句：

- 一次通过
- 第 N 次打回

通过：在对话栏写「一次通过」，不要另加建议。打回：按「总监建议」改代码，改完再把总监作为最后一步调出。

## 书记

书记比总监更根本：每次谈话都要出现。书记不参与决策。

书记是最后一个任务。谈话里的事情全部做完才派，包括总监已经交回的情况。总监排在书记前面。没有例外。

书记的工作区是 `library/`。按 `agent_tasklist/secretary.md` 把用户的问题、任务、主代理和子代理的执行补进当前的 `worklog-xxx`。当前册超过 10000 字就另开下一册。用户说停，书记也不再派。

## 停止

用户说「停止」「停」或 stop：不再派任何子代理。已经派出的，不再根据它的结果派下一次。

第 3 次仍是打回：停下来把三次结论告诉用户，不再派第 4 次。
