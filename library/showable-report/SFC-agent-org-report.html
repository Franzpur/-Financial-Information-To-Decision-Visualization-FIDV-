代理组织架构

部门权责与隶属 · 截至 2026-10-07

三部门平级：总参谋部、监理部、档案部。美工部与信息部不是第四个部。
父代理是唯一派出者，也是跨域产品代码的写手。部门之间互不隶属、互不调度。

2. 三部门

部门职权不做
总参谋部 读工作日志、概念与工程结构，把要求拆成意志和任务列表。可调度美工部、信息部、参谋纪要官。业主安排时，可改这些可调度角色的文件。一旦呼出，必须第一个执行。 不写产品代码。不调度、不指导、不改写监理部与档案部，含三属和书记、秘书、运维。
监理部 产品代码改完后的终裁。三属并列取证，监理部只写三监报告。三属都达标才通过；任一不达标，整单打回。上限三次。打回后三属整单重审。 不改设计，不写实现，不改文件。无代码改动则不审，不空转三属。通过时不另加建议。
档案部 调度书记、秘书、运维。工作区在 library/。秘书写可打印文稿；运维记运行故障。 不代替每次谈话末尾的书记。不写产品代码。不调度监理部、总参谋部、美工部、信息部。

3. 隶属各职

职隶属权责
参谋纪要官 总参谋部 钉口语到概念、列未拍板、对照意志回流。只读，不改产品，不写通过或打回。只经总参谋部任务单派出。
美工部 受总参谋部调度 网页与启动表层美学。在美学专知路径内可改外观。不写通过或打回。
信息部 受总参谋部调度 读数、词条、乱缺建议、彭博公式表。在数据专知路径内可改数据工程。不改产品服务端，不写通过或打回。
工程测试属 监理部 这次改动能否打开、有没有阻断性报错。截图，看画面是不是这次要的结果。无界面则写明无影像面，并检查入口仍可打开。
代码质量属 监理部 四问：是否服务这次功能，是否简洁，是否与以往连贯，是否不外溢。任一为否，本属不达标。
理念贯彻属 监理部 只按设计理念三条判断：专业化、标准化、可操作化。不审能不能打开，不审是否外溢。
书记 档案部 每次谈话的最后一项。只记 library/worklog-xxx.md。不参与决策，不写报告。
秘书 档案部 业主要文稿或档案部调度时，写 library/showable-report/。不是每次谈话必派。
运维 档案部 故障已现或业主要记 bug 时，写 library/bug-report/。不是每次谈话必派。

4. 一次改码怎么走

  1. 父代理判定呼出。若是总参谋部，它最先执行，交出意志和任务列表。
  2. 按单调度美工部、信息部或参谋纪要官。专知内由该部改；跨域由父代理改。
  3. 有产品代码改动：父代理送监理部。监理部列出同一份材料。三属并行取证，互不看对方结论。
  4. 监理部写三监报告。通过则父代理可以宣布这一改完成。打回则按不达标的那一属已写的句子再改，三属整单重审，最多三次。
  5. 谈话最后派书记记工作日志。

讨论和规划、还没改代码、也没点名监理部：不送三监。

5. 写码权

谁可写不可写
美工部 外观：样式、页面结构与 class、开屏与玻璃 chrome、启动器色板与图标。 坐标、抽出与焦点几何、产品数据流、启动器的进程与端口。
信息部 数据表、摄入脚本、词条、本机实体库。 产品服务端、立方体几何、美学文件。
父代理 坐标与产品逻辑，以及上面两行以外的路径。视觉和逻辑缠在同一文件时，整文件归父代理。 —
总参谋部、纪要官、档案部三部、监理部及三属 无产品改码权。 不因权知条款获得写产品的权力。

6. 怎么点名

「电」加角色名。例如电总参谋部、电监理部、电档案部、电美工部、电信息部、电书记、电秘书、电运维。

总参谋部还可由「报文」「报」「M」「Message」或直接呼出。三属不单独点名开工，只在监理部送审时派出。参谋纪要官不单独接产品单。

旧称现在
总监、chief inspector、产品理念监督、电总监监理部。不再由一个人对照理念一次点头。
书记处、Secretariat、电书记处档案部。职能仍是书记、秘书、运维。
