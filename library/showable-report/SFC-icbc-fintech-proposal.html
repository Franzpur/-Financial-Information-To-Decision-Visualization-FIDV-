ABSTRACT

摘要

SFC（Standard Financial Charting，标准金融制图）是一套给金融工作者使用的决策可视化工具：把大量行业与企业信息放进同一套标准化的坐标里，看、移、点，帮助在信息过载的情况下做判断。

第一版只做一件事：服务风险控制，尤其是债务风险，并以企业为节点观察风险如何沿产业链传导。本次首测（First Test）选取 AI 产业链作为示范对象，参赛方向为科技金融。

目前已经完成并可运行的部分：以彭博 BICS 行业分类为标准的行业展板与四级公司名单；一个三维的产业链制图台，其中公司是切片上的点，企业之间的收入关系是点到点的线；一个可以双击打开、数据与计算全部留在本机的 macOS 应用。后端与前端按 26 个模块、35 条关系组织，模块图与代码一一对应。

如实说明　NOT YET DONE

债务风险沿企业节点传导的完整画面尚未画出；制图台上的 AI 产业链目前是一条演示链，公司与行业分类尚未统一到 BICS；三维图表导出与自制图表，理念已定，产品未做。本计划对未完成部分一律如实写明，不与已实现部分混写。

我们没有自造新的风险指标。判断风险的指标，与其说是被创造的，不如说是被广泛接受的。我们做的是让被广泛接受的指标和概念，在统一的坐标里被看见、被比较。

1.1项目定位

SFC 面向金融工作者，解决一个具体问题：金融信息如此之多，如何容易地了解最重要的信息，从而做出决定。我们的方法是可视化，并且是标准化的可视化。

第一版的取舍写得很窄：行业上，注重人工智能相关的科技行业；判断上，注重风险控制；风险类型上，注重债务风险；画面上，注重以企业为节点的风险扩散与传导。不服务于这个判断的装饰、泛资讯、无法追溯来源的数字，不算本产品的功能。

1.2名称与含义

SFC 是 Standard Financial Charting 的缩写，中文名「标准金融制图」。三个词各管一件事：

  • Standard（标准）：概念统一、分类有依据、视觉统一。同一概念全站只用一个名字。
  • Financial（金融）：数据专业、来源可追溯，服务金融判断。
  • Charting（制图）：不是静态图片，而是可以操作、可以移动、可以导出的图。

1.3参赛方向与范围

参赛方向为科技金融。理由全部来自第一版设计：服务金融工作者判断；行业上注重 AI 相关科技行业；判断上注重风险控制与债务风险；可视化以企业为节点。

本计划只写本团队已有的工程、已有的数据和设计里已经写明的下一步。大赛公布的其余方向不是本计划的工作内容。

2.1大量信息下的判断困难

金融工作者面对的不是一个已经收好的结论，而是大量公司、大量分类、大量指标。判断一家公司落在产业链的哪一段，先看什么，需要在分类、财务、关系之间来回翻查。信息越多，越需要一个统一的位置感：它在哪里，它和谁相连。

2.2现有做法的缺口

我们观察到的缺口有三类。本计划不提供市场规模或用户数据。

  1. 分类不统一：同一概念在不同材料里有不同叫法，同一公司在不同表里归属不一。
  2. 图与图之间无法对照：静态图一图一用，换一个问题就要重做一张，且几张图之间没有共同的坐标。
  3. 关系看不见：企业之间的收入关系、债务联系，通常存在于表格与文字里，没有被画成节点之间的线。

2.3为什么先做 AI 产业链债务风险

首测选 AI 产业链，是因为这条链上资金需求大、环节多、企业之间相互依存，关系密、链条长，适合检验「以企业为节点看传导」这个想法。选债务风险，是因为第一版设计把风险控制与债务风险定为重心。

2.4我们的切入点

不做新的风险评分，不做预测。做三件事：

  1. 把行业分类统一到一个公认标准（彭博 BICS）上。
  2. 把位置统一到一套标准坐标里，让不同的图可以在同一空间里叠放和比较。
  3. 以企业为节点，把企业之间的关系画成线，并保留数据来源，使每个数都可追溯。
重点　KEY POINT

不造新指标，只做统一的坐标。统一分类、统一位置、画出关系、保留来源，是 SFC 在首测中的全部主张。

3.2三类坐标

SFC 用三类坐标，名称不混用。没有统一的坐标，就没有可操作的视图。这是后面所有功能能够叠放、移动、对照的前提。

表 3-2三类坐标
类名称作用
1 类位置坐标 (s, x, y)制图台里唯一的摆放语言。s 为切片轴（前后），x 为左右，y 为上下；每个面上 x、y 取 0 到 10。
2 类相对坐标（环上位置）公司点在切片面内的位置，由某个量在本切片内的相对大小决定。
3 类行业坐标公司在彭博 BICS 里的行业归属，七段、每段两位数字，如 12-11-11-11-00-00-00；展板与名单只显示前四段。不参与摆放。

3.3决策路径：展板、名单、制图台

产品的主路径是三步：

  1. 展板：彭博 BICS 的一级到三级是同一块行业展板。每个格子显示四段行业坐标和该支下的公司家数。页眉有搜索框，可以按公司名片段或代码定位，用上下键选择，回车确认。
  2. 名单：点四级格进入该四级的公司名单。一行一家公司（以完整成员代码为身份）；该公司的主要业务以收入占比最大的一行为准。名单可以按主要业务收入排序，可按上市地筛选。
  3. 制图台：点名单里的一行，进入该公司的制图台。从名单进入的是单公司标准壳体：该公司位于坐标 (5, 5, 5)。若该公司是已有关系数据的产业链中心（目前为英伟达），制图台会按其上下游建出切片与收入线。

沿面包屑可以逐级返回；Backspace 在焦点不在输入框时向上一级返回。

3.4制图台的构件

制图台只允许四类视觉构件，每一类对应一个已命名的概念：

  • 切片：一张平面代表一个产业链环节。
  • 公司点：与切片共面的环，美国与非美国用不同颜色的边。
  • 同心环：把某个量在切片内的大小，用距圆心的远近表示。圆心表示最大。
  • 收入线：企业之间点到点的线。供应方向与客户方向用两种颜色区分。

操作上：点击切片或公司以聚焦；聚焦的切片留在原位，其余切片就地淡出；可以钉住多个切片同时保留；切片间距可以在 0% 到 200% 之间调整，间距收到 0 时多张切片叠合，便于并排对照；一键回到标准视角；搜索公司后自动对准并展开该公司的聚焦页。

4.1总体结构

前端与后端分离：

  • 前端是浏览器页面，只通过一个接口模块用 HTTP 取 JSON，不直接读任何数据文件。
  • 后端是一个本机的 Python 服务，只绑定本机回环地址，独占数据库和数据文档的读取权。
  • 本机原生外壳（Swift，macOS 窗口加 WebKit 视图）把二者包成一个应用：打开时自己拉起内嵌后端，关窗时一并退出。

前端一律经单一接口访问后端；外壳不向页面注入任何原生桥。

工程由 26 个模块、35 条关系构成。模块图的真源是一份结构化文件，由脚本生成静态图，几何检查为零交叉、零重合。

4.3本地应用

2026-10-14 至 15 完成从网页到应用的改造，模块结构不变：

  • 双击 Standard-Financial-Charting.app 即得一个独立窗口，窗口内就是原界面。
  • 应用自己拉起内嵌后端、自己选择可用端口、关窗即退，崩溃或卡死时有限次自动重启。
  • 通用二进制（arm64 与 x86_64），启用 hardened runtime。
  • 自带 Python 3.14.8 运行时与本地化的 three.js，无需安装任何环境，可离线运行。
  • 数据与计算全部在本机，无遥测，无需账号。

当前签名状态是 ad-hoc、未经苹果公证（本机尚无开发者证书）；签名与公证流水线已就绪，由环境变量开启。应用仅支持 macOS 11 及以上。

4.4质量保障

  • 回归脚本分三档：采集基线、快速档（模块图、静态检查、60 条接口响应与基线逐条比对）、完整档（再加应用自检与生命周期测试，并覆盖已构建的两种发布包）。
  • 模块图生成有几何检查（零交叉、零重合、线不压框）。
  • 每次改动按设计三原则审查；审查分工程测试、代码质量、理念贯彻三项并行。

5.2数据处理规则

规则全部成文，且同一规则全站贯通：

  • 身份：一家公司以完整的成员代码为准。同一公司在多个行业表里出现，是收入分段，不是重复身份。
  • 主要业务：同一代码下，收入占比最大的一行为主要业务；占比为空的不当作 100%；并列时依次按行业收入、四级代码、来源文件、编号定出唯一一条。
  • 空占比：占比为空的公司仍进名单，其行业坐标前加负号表示「占比缺失」；有数字的永远优先。
  • 金额：行业收入保持表内的美元完整金额，不换算；制图台上的 B 是十亿美元，由原值除以十亿得到，只在制图台载荷里发生。
  • 上市地：取自彭博代码里的交易所码并映射到国家，不是总部所在地，也不是制图台的美国／非美国颜色。映射不到的归「未映射」，不猜。
  • 缺口：数据缺口先写建议，不写成「已修复」。

6.1首测要回答的问题

首测只问一个问题：在 AI 产业链里，一家公司落在哪一段，它的上下游是谁，债务风险先看哪里。

这个问题拆成能指认的三件事：这是哪一家；它在 BICS 里的行业坐标是哪一段；它在制图台里是哪一个节点、与谁相连。前三件已能演示；债务风险如何沿节点传导，是下一步，6.8 明写。

6.2方法立场

团队曾设想自造一套基于企业间债务联系与收入构成的新财务指标，后来放弃了。理由有两条：好的风险指标既简洁又有逻辑，公信力来自被广泛接受；而我们不完全熟悉会计准则和风险评估体系，做不出能服众的新指标。

判断风险的指标，与其说是被创造的，不如说是被广泛接受的。

SFC 方法立场

因此，首测的方法立场是：

  1. 指标与概念，采用金融领域已被广泛接受的口径，不自创评分。
  2. 我们的贡献在可视化的基础：统一分类、统一坐标、把企业之间的关系画出来，并保留数据来源。
  3. 哪些指标进入图中，由团队在 6.7 确定（定稿待填写）。

6.3产业链框架

演示库把 AI 产业链分为 11 层，从能源到模型：电力在后端（小 s），模型在前端（大 s）。这是早期演示链，不是 BICS 展板里那张公司表，两者尚未统一。

6.4示范一：行业定位

从展板进入，逐级下钻到某个四级行业，可看到该行业的公司家数与行业坐标；名单中的公司可按主要业务收入排序。以 AI 相关的科技行业为例，路径是：技术（Technology）→ 其下的子行业 → 四级。

6.6示范三：债务期限折线（演示）

聚焦某家公司时，若其有债务日程，聚焦页底部显示一条按时间排列、单位为十亿美元的折线。目前只有演示公司有这条数据，且数字为示意，用来验证「聚焦页能承载财务序列」这一路径，不是真实公司的债务数据。

6.7风险落点的研究对照

我们读过多家卖方研究机构对 AI 产业链的分析，仅用作方法对照，不转载其图表、原文与数字。读后的结构性印象是：

  • 风险的位置因环节而异。需求与订单环节的风险多被写成利润率与供给限制，而不是需求中断；云平台环节被写成资本开支的回报与自由现金流是否跟得上；电力与托管环节被写成交付与杠杆。
  • 同一家公司，不同机构给出不同判断；因此一张图不应把分歧合成一个分数。
  • 一张图只回答一个问题；比较并排而不相减；论点用路径，截面用于归档。

这些印象对制图台的约束是：营收环继续只表示营收；债务、资本开支、积压各自留名，作为另一条命名的线，不加进营收；传导是企业节点之间的线，线的名字是「债务」或「义务」，而不是把营收环涂成风险色。
