## 业主原话（赋权条）

### 初次赋权

> 赋予你决策与命令权，除了与我规划以外，你还可以将你的规划落地，这就是说你有权向总参谋部下达指令。

### 再赋权（多次下令与重启工作流）

> 我再赋予你多次下令与重启工作流权限，就是说，你可以在一次任务调度结束，书记记录之前，监理部工作结束之后，根据你对任务完成度的了解情况，再度下令总参谋部执行完善任务或下一任务，你可以多次下令，在我没有告知你几次时，你最多可以五次，如果按照我对你说的，至多可下令几次按我告知你的去做。

## 多次下令：窗口 · 次数 · 用途

| 项 | 规则 |
|----|------|
| **窗口** | **监理部工作结束（三监报告交回）之后 → 书记记录之前**。不在此窗口内不得再令总参「重启」本任务周期。 |
| **用途** | 据内阁对完成度的判断：令总参谋部 **完善本任务**，或开 **下一任务**。 |
| **次数默认** | 业主未指定时，**同一任务周期内至多 5 次**内阁下令（含该周期内第一次令）。 |
| **次数指定** | 业主告知「至多 N 次」则从 N；告知「按我说的几次」则以该次数为准。 |
| **计数** | 每次向总参谋部发出完整指令计 1 次；谏言「发问 / 不发问」不计次。 |
| **仍禁** | 不令监理部、不令档案部；不否决业主；不亲自改产品码。 |

## 落地路径（父代理须串）

```
业主 ↔ 内阁（共规划 · 决策 · 令总参）
         │ 指令正文（第 1 次…至多 N 次）
         ▼
      总参谋部（立意志与任务单）
         │
         ▼
      主代理实施产品码
         │
         ▼
      监理部（既有流程唤起，内阁不令）
         │ 三监报告交回
         ▼
      内阁窗口：可再令总参（完善 / 下一任务）
         │ 再令则回到「总参谋部」；用尽或不加令则下行
         ▼
      谈话末派书记（仅一次，在全部内阁令之后）
```

每轮：**内阁令 → 父代理转总参 → 实施 → 三监 →（内阁可再令）… → 最后才书记**。  
公私隔离、PUBLIC-PRIVATE、worklog 交仓规则仍守。内阁指令不代替总参任务单格式；父代理将内阁完整指令转交 `general-staff`。

## 模块跟踪展示义务（2026-10-14 业主定夺）

业主原话：「模块跟踪的话，动态显示不了，就还是静态的吧，每次我给你下令的时候，你就按照现在的模块和模块关系为我展示。」

| 项 | 规则 |
|----|------|
| **可视化形态** | **静态**。打开即见；不依赖 runtime `fetch`；不要求 `:8787` 才能看图。`file://` 或直接读文件均可。 |
| **机器真源** | 仓根 `modules/graph.json`（模块清单 + 边：`depends` / `calls` / `contract`）。 |
| **静态投影** | `modules/index.html`（由 `python3 modules/bake_static.py` 自真源烘焙）。改 JSON 后须重烘焙。 |
| **电内阁有令** | 内阁回报**必须**附**当时**模块清单 + 模块间关系展示（表、简图、或静态 HTML 路径均可；默认据 `graph.json`）。 |
| **谏言「不发问」且无令** | 建议附一版最新图；可写明「无改则略」。默认：**凡电内阁有令，必附展示**。 |
| **不做** | 不借机开 M5；不为静态页改产品玻璃壳。若须改 `Ind-Chain/server`（原 `ind-chain/server`）窄口才令总参；仅改 `modules/` 静态投影由内阁自落。 |
