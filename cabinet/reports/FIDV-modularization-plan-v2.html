1.1 DESIGN 三持 → 模块必须服务什么

持对模块化的硬要求
专业化模块边界按「判断债务 / 传导 / 企业节点」切，不按「文件好拆」切。装饰面、不可追溯数字不得成为独立产品模块。

2. 理想化切分原则（写死）

  1. 目的先于目录。 先有理想模块 ID 与契约，再映射到路径；不得因「现在在一个文件里」就把两职责粘成一模块。
  2. 前端按功能模块。 一个功能模块 = 一种用户任务面（或一种跨页共享能力）。不是「一个现有 .js 文件 = 一模块」。
  3. 后端按库的类型。 一个库型模块 = 一种数据职责与失败域（演示 SQLite、BICS 层级、实体名单、NVDA 链文档、上市地映射…）。不是「app.py 里一段函数 = 一模块」。
  4. 接口畅通优先于无 bug。 契约写清：字段表、空值语义、谁算环、谁不得打开哪类文件。模块化不承诺消灭缺陷；承诺邻块可对接、可替换、可分失败。
  5. 前后端分离（本仓定义）。 浏览器只认 HTTP JSON / 静态；服务端独占库文件与链文档。分离的是打开权与计算权；本阶段允许仍是一个本机进程 127.0.0.1:8787。
  6. 以指令或结构为接口。 合法接口仅：（A）HTTP 路由 + 字段结构；（B）C-* / state 指令交接；（C）仓级路径契约（公私、摄入）。口上没有的字段 = 不存在。
  7. 同一三维空间。 演示链、壳、NVDA 链共用坐标核与场景壳；变的是载荷，不是第二套引擎。
  8. 风险隔离。 一块失败，邻块只看见契约上的空 / 缺 / 旧值，不得改道偷读另一库「补全」。

  bics: BicsNode
  listingCountry: string | null
  entities: EntityRow[]   // 主业胜出后的一行一 ticker
}

生产者：BE-ENTITY + BE-LISTING。消费者：FE-LIST。禁止用 companies.json 行顶替。

7.4 结构面：Bundle（立方体唯一装载物）

Bundle {
  meta: {
    mode: "demo" | "shell" | "nvda-chain"
    title: string
    ticker?: string
    shell?: boolean
    chainMode?: boolean
  }
  layers: Layer[]           // demo / nvda；shell 可为 []
  companies: Company[]      // 已含 revScore/ring/ringCos/ringSin
  revenueLinks: Link[]      // demo/shell = []
  countries?: ...
}
Company {
  id, name, ticker, country,   // US|intl 归属色
  layerIndex | s,              // 与 layers 对齐
  coord?: {s,x,y},             // 或由相对坐标投影
  ring, revScore, ringCos, ringSin,
  linkPct?: number, side?: "supplier"|"customer",
  legalEntityCoord?, bondSchedule?, sourceDetail?
}
Link {
  fromId, toId,
  kind: "supplier"|"customer",
  label?: string
}

规则：环位与相对坐标只在服务端写入；浏览器不得因 Filter 重算环。SCENE 只消费结构，不补算。

9.4 迁移顺序（建议编号，供总参日后拆任务）

顺序原则：先契约畅通，后目录搬家；每步可独立验收接口，不要求一次理想树。

  2. M2 FE-API 收拢 — 闸门/名单/立方体只经 FE-API。验收：改一处 base path，三页仍通。
  3. M3 BE 库型抽离（逻辑边界） — BICS-HIER / ENTITY / NVDA-LINKS / CHAIN-LAYOUT / SHELL 成独立模块（可为同目录多文件）。验收：HTTP 边变薄；单测可对 CHAIN-LAYOUT 喂夹具 JSON。
  4. M4 BE-BUNDLE 显式编排 — 唯一分派点。验收：新 mode 只需挂编排器，不改 SCENE。
  5. M5 FE-SCENE 子面 — GEO / INPUT 导出面清晰；CHROME 只打 STATE 指令。验收：改 Filter 布局不动建片代码。
  6. M6 FE-NAV 单点 — Backspace/面包屑/history 规则一处。验收：三页导航行为表可对照 CONCEPTS。
  7. M7 INGEST 原子替换 — 实体库替换无空窗。验收：替换中名单读旧库或明确 busy，不空读。
  8. M8（可选）目录理想化 — 包路径改到 §9.2 目标形态。验收：行为零变化，仅路径迁移。

M1–M4 服务「接口畅通」；M5–M6 服务前端功能面；M7 服务库型可靠；M8 是化妆，可最后做。
