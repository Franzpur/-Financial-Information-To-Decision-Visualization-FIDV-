2. 问题与风险

2.1 已观察到的耦合（代码事实）

  1. 服务端单体文件。 app.py 同时拥有：静态托管、BICS 索引、成员主业折叠、壳层组装、NVDA 动态切片与环位、演示 bundle。改一处易牵动无关路由的审查面。
  2. 演示库连接偏早。 _api 在非 BICS 路径上先 connect() 演示库，再分发 bundle——带 ticker 的壳/NVDA 路径概念上不依赖演示库，但调度上仍打开它（前份方案已点名；尚未落改）。
  3. 行业节点与主业计数缠在同一响应。 bics_children 现夹 companyCount 等；失败模式混在一起——层级缺与成员库缺不易分失败。
  4. 前端体积偏斜。 scene.js 兼几何、相机、点选、stay 显隐、收入线绘制；与「场景交接」契约叠在同一文件，风险隔离靠约定而非结构。
  5. 首页/名单自建 fetch。 立方体走 api.js；闸门与名单各写 URL——日后字段改名易漏一侧。
  6. 摄入替换非原子。 现行 ingest 写入前删活库（前份方案「替换成员库」未落）。写入失败窗口可致名单/壳层同时空。

3. 目标边界（须守住）

  1. 前后端分离（本仓定义）。 浏览器只认 HTTP JSON / 静态资源；不打开 sqlite、不读 DATA-SPACE、不读收入线文件。服务端独占库文件与 JSON 真源，把环位算完再交。分离的是文件打开权与计算权，不是「必须拆成两个部署单元」。
  2. 风险隔离。 一块失败，邻块只看见契约上的空 / 缺 / 旧值，不得改道读另一块的内部文件「补全」。
  3. 指令或结构为接口。 合法接口仅三类：（A）HTTP 路由 + 字段表；（B）CONCEPTS 符号 C-* 与 state 交接字段；（C）仓级路径契约（公私、专知写码口、电召）。口上没有的字段 = 不存在。
  4. 同一三维空间。 模块化不得拆成互不相通的多个 3D App（DESIGN §3）。
  5. C-* 概念面。 几何与交互语义以 CONCEPTS.md 为准；信息部不改 C-*；改三维前先对 ID。
  6. DATA-SPACE 边界。 仅摄入脚本与信息部 desk 可读原始表；产品运行时只读已生成的成员库 / 公开层级 JSON。报告与公仓不写密钥、不写不可上云明细。
  7. 组织边界（挂钩，不代替实施）。 总参谋部规划；监理部三监终裁；档案部 worklog/报告/运维；内阁整理与谏言、不写产品码。美工 / 信息专知内写码；交叉整合仅经 GS 调度。

10. 风险与不做什么

10.1 迁移自身的风险

  • 拆 app.py / scene.js 时行为漂移（尤其 NVDA 半盘、stay 全隐、Filter 与 A/F 同开）。
  • 「统一 api 客户端」时改坏闸门 listingCountry 无刷新语义。
  • 原子替换成员库若校验过严，会导致长期停在旧库——须在信息部词条写清校验最小集。

10.2 明确不做什么
