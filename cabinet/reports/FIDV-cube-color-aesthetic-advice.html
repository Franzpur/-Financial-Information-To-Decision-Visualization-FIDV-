决策立方体色彩方案与美学建议

内阁读本 · 2026-10-13 · 产品树 ind-chain/ · 不实施、不否决

业主 Purkniv 电内阁：据 AESTHETIC、COLORS、CONCEPTS（C-POINT / C-REV-LINK / C-ALT / chrome）、briefing 工程影像与 worklog-006 #200–205，提出色板与美学改进看法。

1. 现状摘要

工程已分两层色：chrome 真源在 agent_tasklist/AESTHETIC.md / app.css；立方体数据材质在 state.js 的 COLORS，轴色另写在 scene.js（未入 COLORS）。近条已落地：米白盘 + US/INTL 色环边、半盘坐标、墨绿/暗红收入线、A/F、钉片 stay。

briefing 05-cube.png 仍是旧底栏 chip 壳；现 chrome 已迁到左上 Filter / A/F 与玻璃浮层。影像仍有效：总览下同心环密、标签叠、冰蓝结构线与青点抢读。

2. 建议色板（立方体为主）

原则：三层语义不混——结构（切片/轴/导环）用冷钢蓝灰；归属（上市地）固定 US/INTL；关系（收入线）用墨绿/暗红。chrome 强调色只服务控件，不进点/线语义。

3. 美学改进建议（可编号）

必须改 M

  1. M1 · 收入线对比 — 墨绿/暗红上提明度（上表），否则 NVDA 链半盘关系在总览几乎不可扫读。
  2. M2 · 导环让位给点 — 压暗/减不透明度导环；默认 overview 或点密时鼓励 A/F「藏环+切片」，把关系与点留在前场。
  3. M3 · 轴色入 COLORS — 消灭 scene 私有冰蓝与 COLORS.US 的无意撞车；改一处、概念一处。

酌情 O

  1. O1 · 降默认 emissive — 悬停/选中再亮；与「简洁第一」一致。
  2. O2 · 聚焦时切片面略实、总览更透 — 同一 PLANE 色，只调 opacity；不引入第二色。
  3. O3 · 标签密度 — overview 只显层名或焦点邻层；共面标签在 d 小、层多时易糊成一条（影像已见）。
  4. O4 · HUD 图例 — 底浮一行极简：米白盘 + 青/橙边 = 美/非美；绿线/红线 = 供/客。不恢复旧 chip 墙。
  5. O5 · 门厅/名单 — 继续单色格阵；accent 仅 hover。与立方体「一进三维才开语义色」的落差可保留，但立方体入口处用一句 muted 说明即可。

仅看法 V

  1. V1 — 米白盘是正确锚：把「实体公司」从线框里托出来；勿改回纯色发光球。
  2. V2 — 半盘（供 x<5 / 客 x>5）是空间语法，色只是复述；色改不能替代半盘几何。
  3. V3 — A/F 与钉片是美学工具不只是功能：密场景下「藏结构、留关系」应成为标准读法之一。

4. 设计问题看法

  1. 语义层叠不够分层 — 结构线（轴、导环、EDGE）与数据点（US 青）同处冷色高亮带，影像上点被线网吃掉。设计意图应是：结构淡、归属亮、关系次亮。
  2. 色源分裂 — chrome 有 token，立方体有 COLORS，轴又在 scene。延展时易第三套。
  3. 关系色过沉 — #201 落地的墨绿/暗红概念对，工程值偏印刷墨、偏暗底工程屏。
  4. Glow 与简洁张力 — 环边 emissive + CSS box-shadow 双晕，近距炫、远距糊。
  5. 壳层 vs NVDA 链 vs 演示链 — 三种立方体信息量差极大；壳层空墙正确，但用户从名单点进若期望「链」，空壳易被读成「坏了」而非「标准壳」。这是信息架构，不单是色。
  6. briefing 资产过期 — 05-cube.png 仍画底栏 Filter chips；对外讲稿与现产品不一致。内阁只记看法：展出图应换一帧现 Filter/A/F。

5. 视角问题看法

状态可读性看法
Overview (24,21,21)→原点 层叠透视正确，但导环在此角形成莫尔纹与中心糊团。宜：默认略压导环，或进入后提示 A/F；层标签应收束。
Focused (s*+10,5,5)→面心 最佳读盘面；共面环此时近似正圆。设计应默认「细读用 focus / C」。Overview 只做方位图。
d→0 点半径缩小 + 层贴合：半盘与全局相对坐标是救命绳。线在圆心附近易成束——供/客分色上提后仍可能绞；可依赖 hover 放大与选中高亮，而非再加粗到像面。
半盘 左右语法清晰。斜视时共面盘变椭圆/线，边缘点难点——hover 1.5× 已对症；勿改回 billboard（与 #192 意志相反）。
Stay / 钉片 非 stay 就地全隐（废 −x 残影）正确，视野干净。风险：用户不知「藏了什么」——HUD 短句「All slices · N visible」需在钉片态写清 stay 数。
自由轨道 vs C 离标准位后无「你已偏航」反馈时，标签与盘的共面关系更难读。看法：离 C 位较远时可 muted 提示「C 回标准」，不强制吸回（守 C-CAM-HOLD）。
Company-zoom 底左放大、chrome 隐去：构图清楚。注意放大后米白盘边缘锯齿与 rim 晕加倍——与 O1 同源。
