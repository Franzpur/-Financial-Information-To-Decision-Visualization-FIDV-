## 执行范围与先后（本令）

只做下列四步，**严格按序**；每步单独可验收后再开下一步。范围限 `ind-chain/`（及为 BE-BICS-HIER / BE-ENTITY / BE-INGEST 所必需的既有路径契约）；不改监理/档案流程；不碰公私隔离外材料。

### 步骤 1 — M1 契约冻结（无大搬家）

**目的模块**：`BE-BUNDLE` · `BE-SHELL` · `BE-NVDA-LINKS` · `BE-DEMO-DB` · Gate 计数面（经 `BE-BICS-HIER` / `BE-ENTITY`）

**做**：
- 书面/代码侧冻结 `Bundle.mode` 三值：`demo` | `shell` | `chain`（或今日等价枚举，名称写入 CONCEPTS / 契约注释，与 FE-CUBE-BOOT 对齐）。
- shell / chain（NVDA）路径**禁止**依赖演示 DB 连接；演示库断档不得拖垮壳或链。
- GateBoard 计数可降级字段（缺计数 ≠ 缺层级）。

**验收**：断演示库文件时，`/cube?ticker=` 壳仍可响应（或明确 miss），不得 500 连环；链路径失败只呈契约空/缺，不串读演示层补全。

### 步骤 2 — M2 FE-API 收拢

**目的模块**：`FE-API`（消费者：`FE-GATE` · `FE-LIST` · `FE-CUBE-BOOT`）

**做**：闸门 / 名单 / 立方体三页只经 `FE-API` 触 HTTP；页内禁止散落裸 URL 字符串复制。

**验收**：改一处 base path，三页仍通。

### 步骤 3 — M3 BE 库型抽离（逻辑边界）

**目的模块**：`BE-BICS-HIER` · `BE-ENTITY` · `BE-NVDA-LINKS` · `BE-CHAIN-LAYOUT` · `BE-SHELL`（可为同目录多文件；**不是**「把 app.py 按函数名切段」）

**做**：
- 各库型成独立模块边界；HTTP 边变薄。
- `BE-CHAIN-LAYOUT` 纯函数、可单测；入参为链关系文档 + 锚点实体，出参为已算环/片的结构；**接口按链产品模板**，今日数据可仅有 NVDA。
- `BE-NVDA-LINKS` 只读文档；`held` 永不进 Bundle。

**验收**：可对 `BE-CHAIN-LAYOUT` 喂夹具 JSON 单测；HTTP 边不再内嵌布局算法。

### 步骤 4 — M4 BE-BUNDLE 显式编排

**目的模块**：`BE-BUNDLE`（唯一分派）→ 子库型；消费者仍是 `FE-CUBE-BOOT` / `FE-SCENE`

**做**：唯一 mode 分派点；新链 mode 只挂编排器，不改 `FE-SCENE`。

**验收**：新增或替换一条链实例（仍可先只有 NVDA 数据）时，不改 SCENE 建片主路径。
