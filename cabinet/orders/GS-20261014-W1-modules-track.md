## 指令正文（须完整执行）

### A. 前后端分离（本仓定义 · v2 §W1 / 前后端打开权）

**定义（写死）**  
浏览器（全部 FE-*）只认 **HTTP JSON** 与 **静态 HTML/JS/CSS**（及既有 C-* / state 指令交接）。服务端（全部 BE-*）独占库文件与链文档（演示 DB、实体 DB、BICS 层级、链 JSON/文档、DATA-SPACE 摄入路径等）。分离的是**打开权与计算权**，不是双进程部署。

**允许**  
- 仍是单进程 `127.0.0.1:8787`。  
- 契约已立、目录未拆（延续 M1–M4）。

**验收（硬）**  
1. **FE 路径**不得直接打开：`.db` / 链 markdown（或链真源文件）/ `DATA-SPACE`（含 `file://`、相对仓路径读库、前端 `fetch` 静态数据文件冒充 API）。注释里写 `CONCEPTS.md` 路径不算运行时打开，但**运行时**不得读链 markdown。  
2. **BE** 不得把库文件路径（绝对或仓内可读路径）泄漏给浏览器当作**可读文件句柄**；JSON 可含逻辑 id / mode / 缺数语义，不得教 FE「去打开这个路径」。静态服务仅限 `web/`（或既定静态根），不得把 `.db`、DATA-SPACE、链真源目录挂成可下载静态。  
3. 对照 v2 §7.6：浏览器永不出现运行时只读真源路径与摄入路径。

**对照现状（查漏补缺，勿空转）**  

| 已有（M1–M4，视为已立，勿重做） | 本令须补 |
|--------------------------------|----------|
| `BE-BUNDLE` 显式 mode 分派 | 审计 Bundle / meta / 错误 JSON：**无**库文件绝对路径或可诱导 FE 打开的路径字段 |
| `BE-CHAIN-LAYOUT` 服务端算环 | 确认 FE-SCENE / 页脚本**不**读链文档文件；环位只消费 Bundle 结构 |
| `FE-API` 闸门/名单/立方体收拢 | 扫 `ind-chain/web/**`：无裸路径读 `.db` / DATA-SPACE / 链真源；三页仍只经 FE-API 触 HTTP |
| `meta.mode` demo\|shell\|chain | 保持；本令不改 mode 语义 |

**须补的验收项与改动点（总参任务单必须逐条可勾）**  
- **A1** 静态边界：HTTP 静态 handler 拒绝服务 `web/` 外的库/链/DATA-SPACE；抽检 `/.db`、数据目录、链文档 URL → 404 或非文件泄漏。  
- **A2** JSON 路径消毒：健康检查 / bundle / bics / 404 错误体中，无绝对文件系统路径、无「请打开某 .db」类字段；若需调试信息，仅服务端日志。  
- **A3** FE 打开权抽检：`ind-chain/web/js`（及页内脚本）无 `fetch`/`XHR` 指向数据文件或 `file://`；无 SQLite/WASM 直连库。  
- **A4** 书面一行（CONCEPTS 或契约注释即可）：W1 打开权 + 「单进程允许」。不扩写长文。  
- **A5** 回归：`:8787` 闸门 / 名单 / 立方体（含 shell/chain 契约路径）仍通；不因 A 项加固而破坏 M1–M4 已验收行为。

**不做（A 内）**  
不为 W1 而物理拆分 FE-* / BE-* 目录；不新开第二进程；不重做 M1–M4 编排/API 收拢。

### B. `modules/` 动态跟踪与可视化

**落点（已拍板）**  
`/Volumes/DATA/FIDV/modules/`（仓根 `modules/`）。

**职责**  
动态跟踪：**模块清单**（今日至少覆盖 v2 已用 FE-* / BE-* 与本仓已落地边界，如 FE-API、BE-BUNDLE、BE-CHAIN-LAYOUT 等）与**模块间关系**（依赖 / 调用 / 契约边；边类型须可区分，至少三类之一写清：`depends` · `calls` · `contract`）。

**真源**  
- 机器可读：JSON 或 YAML（择一为主真源；建议 `modules/graph.json` 或等价）。  
- 可由脚本从仓内约定扫描或人工维护生成（`modules/scripts/` 或仓内既有脚本位）；真源变更后可视化须能反映**当前**内容。  
- 真源字段最低集：模块 `id`、侧（`FE`|`BE`|`other`）、短职责、边列表（`from`/`to`/类型）。可增不可减。

**可视化投影**  
- **一个 HTML**（建议 `modules/index.html` 或 `modules/track.html`）。  
- **设计**：与 `cabinet/reports/` 纸面族同系（clerk 纸面感 / 对齐 `SFC-modularization-plan-v2.html` 的纸面 token：暖纸底、墨色字、细线表/图，非产品玻璃壳、非仪表盘堆砌）。  
- **动态跟踪**：打开该 HTML 须反映**当前** modules 真源——**不是**一次性静态报告截图或写死节点的死页。  
- **实现方式**（总参/实施择一写清并落地）：  
  1. 同源 JSON `fetch`（经现有 `:8787` 增加只读静态/API 暴露 `modules/` 真源；或  
  2. 构建/生成脚本注入真源进 HTML；或  
  3. 同页内嵌生成器读相对路径（须可本地打开）。  
- **打开方式须择一并写进任务单**：① 本地直接打开 HTML；或 ② 经现有服务打开。至少保证业主在本机一种方式稳定可见当前图。

**验收（硬）**  
- `modules/` 下真源 + HTML 存在；改真源中一条边或一个模块名后，按所选打开方式刷新/重开，画面随之变。  
- 图或表能看出模块间关系（依赖/调用/契约），不仅模块名单。  
- 不写入 `library/showable-report/`；不冒充秘书展出件。纸面感对齐 cabinet reports 即可。

**不做（B 内）**  
不把 `modules/` 做成第二套产品应用；不调度美工部整面玻璃壳；不借机做 M5–M8。
